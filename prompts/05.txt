## CONTEXTE
Il y a 2 chemins pour passer un ordre GMX dans le frontend :
1. executeGMXOrder() — panneau GMX dédié → envoie collateral_usd ✓ → route vers place_order_by_collateral() ✓
2. executeOrder() — formulaire d'ordre principal → N'envoie PAS collateral_usd ✗ → tombe dans place_order() avec quantity interprétée comme coins ✗

## BUG A — executeOrder() ne passe pas collateral_usd (dashboard.html lignes 5420-5431)
Le payload construit par executeOrder() :
```javascript
var body = {
    symbol: currentSymbol,
    side: side,
    type: orderType,
    quantity: coinQty,
    leverage: leverage,
    mode: 'live',
    exchange: 'gmx',
};
```
Il manque `collateral_usd`. Le backend (server.py ligne 9502) fait :
```python
collateral_usd = float(body.get("collateral_usd", 0))
if collateral_usd > 0 and requested_exchange == "gmx":
    result = adapter.place_order_by_collateral(...)
else:
    result = adapter.place_order(...)  # ← atterrit ici, sizing faux
```

CORRECTION : Dans executeOrder(), quand l'exchange est GMX et que l'utilisateur entre un montant en USDT (qtyUnit === 'usdt'), ajouter collateral_usd au body. Après la ligne 5431 (après la construction de body), insérer :
```javascript
    if (body.exchange === 'gmx' && qtyUnit === 'usdt') {
        body.collateral_usd = rawQty;
    }
```

## BUG B — TP/SL non validés dans /api/execute (server.py lignes 9379-9380)
```python
tp = body.get("tp")
sl = body.get("sl")
```
Ces valeurs ne sont jamais validées. Si tp est une string, crash dans _place_tp_sl_order() à int(trigger_price_usd * 10**30).

CORRECTION : Ajouter validation après la ligne 9380 :
```python
    if tp is not None:
        try:
            tp = float(tp)
            if tp <= 0:
                tp = None
        except (TypeError, ValueError):
            tp = None
    if sl is not None:
        try:
            sl = float(sl)
            if sl <= 0:
                sl = None
        except (TypeError, ValueError):
            sl = None
```
